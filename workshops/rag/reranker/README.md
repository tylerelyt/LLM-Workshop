# 练习一：同一批候选，为什么还要再排一次？

你要给团队知识库选择上线配置。向量召回能找到相关文档，但最终能放进上下文的片段有限。团队希望你判断，哪些问题值得加一道重排，哪些失败应先查召回。

固定问题、候选池和最终入选量。比较纯向量排序与重排后，各自选中了哪些证据，再检查两组回答实际引用了什么。挑一个重排改变了证据覆盖率的问题，再挑一个排序变化了、证据覆盖率却没变化的问题。解释差异来自哪一步。如果必要证据从未进入候选池，指出你会先改什么。

提交两组候选顺序、入选片段和依据，以及对入选量或是否重排的判断。使用 Evidence Recall 和首个相关片段的位置检查结果。若跑线上比较，另记新增调用耗时。

- 离线回放：`python -m workshops.rag reranker`
- 真实运行：`python -m workshops.rag reranker --live`

代码复用 [RAG 课程](../README.md) 的 BGE 嵌入索引、教学语料和证据标注。真实运行使用 DeepSeek Flash 对候选打分并对两组上下文分别生成答案。离线模式读取 2026 年 11 月 1 日的 8 篇文档运行快照。该快照未包含后来并入的支付回滚条款，不能当作当前共同语料的重跑结果。
