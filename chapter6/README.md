# 提示工程方法

把任务要求与外部资料组织进上下文，构建能追溯依据的应用。先理解[模型接口与状态](../chapter4/README.md)，明确资料必须怎样进入当前请求。

## 从最小问答到问题定位

从[基础提示](basic_prompting/README.md)理解任务表达，再用[向量问答](vector_qa/README.md)建立原文、索引、查询与回答的完整路径。向量问答支持自带语料、固定题集和批量运行，可以先建立基线，再比较修改。

出现错误时，沿执行过程定位第一处偏差，再选择相应实验：

| 观察到的问题 | 练习入口 | 要查看的证据 |
| --- | --- | --- |
| 输入没有保留原文信息 | [文档提取](document_qa/README.md)、[图像分析](image_context/README.md) | 页码、原图、OCR 和实际发送的内容 |
| 文档重复、来源或切块有问题 | [语义去重](semantic_dedup/README.md)、[切块反馈](chunk_feedback/README.md) | 原文版本、片段边界与处置理由 |
| 相关资料没有进入上下文 | [检索与重排](reranking/README.md)、[跨语言检索](cross_language/README.md) | 召回候选、译文约束、最终入选片段 |
| 问题需要组合关系或查询数据 | [知识图谱](knowledge_graph/README.md)、[图检索](graph_search/README.md)、[NL2SQL](nl2sql/README.md) | 关系出处、证据链或只读 SQL 结果 |
| 已有原文仍回答失实 | [合同原文问答](legal_qa/README.md)、[基础提示](basic_prompting/README.md) | 具体断言、支持它的原文与证据缺口 |

表中的实验各自提供教学素材；根据失败原因选择方法，再把修改带回原来的问题集验证。增加候选或换一个模型后，仍要检查是否真的改善了目标问题。

## 用自己的文档完成一次迭代

在[向量问答](vector_qa/README.md#从教学语料到自己的文档)中准备自己的文档和参考问题，记录召回、回答、引用和耗时。保留有依据、需要多条证据以及无法回答的问题，检查一次修改帮助了哪些问题、损害了哪些问题。

需要让 Agent 主动查询时，继续完成[检索服务接入 Harness](../chapter9/rag_mcp/README.md)。这一步增加工具发现和调用，原文依据、版本与回答质量仍需要分别核对。

## 参考阅读

- [RAG：面向知识密集任务的检索增强生成](https://arxiv.org/abs/2005.11401)：理解参数知识与外部检索的结合，对照问答实验中的检索器与生成器。
- [大语言模型检索增强生成综述](https://arxiv.org/abs/2312.10997)：梳理索引、检索、增强与生成的设计空间，按失败环节寻找改进方法。
- [BGE M3-Embedding](https://arxiv.org/abs/2402.03216)：了解多语言、稠密、稀疏与多向量检索能力，对照练习实际采用的表示方式。
- [GraphRAG：从局部到全局的查询聚焦摘要](https://arxiv.org/abs/2404.16130)：理解图结构与摘要怎样支持全局问题，与本地关系扩展实验比较适用场景。
- [RAG 与微调：流水线、权衡及农业案例](https://arxiv.org/abs/2401.08406)：结合具体任务分析数据更新、知识使用与适配方式，避免脱离场景选型。
- [LayoutParser：文档图像分析工具包](https://arxiv.org/abs/2103.15348)：理解版面结构的作用，回看纯文本提取和 OCR 会遗漏哪些信息。
