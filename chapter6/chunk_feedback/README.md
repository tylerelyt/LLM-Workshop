# 切块质量反馈

知识平台上线了按项目检索。项目迁移后，值班人员发现，有的正确回答收到差评，有的好评也来自一份混着无关引文的回答。你负责把回放日志变成两种可用结果：需要维护的片段，以及可以拿来训练检索的查询—片段样例。

## 工程任务

回答收到好评不代表每个引用片段都有用，差评也不代表片段本身错误。

在 [lab.py](lab.py) 中，固定回放与一份复核响应，只把一条返回引文换成原文不存在的句子；可用脚本响应替身检查守卫，明确标注回放。

用问题与原文解释维护标签，指出哪些记录能进入训练候选、哪些必须人工复核。

## 已有材料

`lab.py` 中的 `CHUNKS` 是带版本的片段原文。`REPLAY` 记录查询、匿名用户、回答级反馈，以及每个片段经历了哪一步。

- `recalled` 表示检索召回，`loaded` 表示进入模型输入，`used` 表示实际用在回答里。
- 已有复核判断为 `supports`（支持当前回答的正确依据）、`contradicts`（与已核验规则冲突）、`irrelevant`（被采用但对本题无用）。`None` 表示证据不足，仍需复核。
- 这份材料是课堂回放样本，可以重复运行，未连接生产知识库。

先检查默认输出中的 `maintenance`、`alignment_samples` 与 `attribution_counts`。选中 `REPLAY` 的 `t11`，只翻转回答级好差评，保留查询、片段原文及已核验的 `supports` 标签，再运行。预测反馈计数会变，但 `t11` 的有效正样例仍应保持正标签。用这两处实际变化解释“用户评价”和“片段能否支持本题”各自提供什么证据。

这次修改范围是 `REPLAY` 的单条反馈，处置规则和核验数据保持固定；恢复反馈即可重做。若进一步调整高频阈值，应另存结果并解释分类边界变化，默认样例的固定分类检查也要据此重新分析，不能把换阈值后的失败直接视为实现错误。

## 你的任务

整理一份片段处置清单和一组对齐样例，并为每条结论保留查询、片段版本与可追溯的回放依据。

1. 分开统计已核验使用的回答好差评和独立核验的片段标签。从跨用户、跨查询的使用记录中识别经常有用和经常误导的片段，分别决定如何维护。说明怎样处理高频但证据不足或结论分歧的片段。
2. 为证据充分的低频查询—片段关系整理正负样例。选一个同一片段在两个问题中作用相反的例子，说明为什么给出相反标签。
3. 检查两个容易污染数据的边界：回答反馈与片段证据冲突，片段只被召回或装入、没有用于回答。证据不足的记录留给复核。
4. 写一份在线 A/B 评估方案。对齐模型与自己的索引配套，固定片段、生成模型与提示，说明随机分组、反馈覆盖和成本的比较口径。

能否证明方法有效，要看你的处置结果和查询—片段样本能否对回原始记录。复核时会换一条反馈方向、增加一条仅召回记录，检查它们是否凭空产生片段级证据。若新增曝光恰好跨过高频阈值，说明该片段为什么进入高频复核队列。阈值可以调整，结论应能从覆盖情况和已核验证据推出。

## 运行和核对

使用 Python 3.11 或 3.12，运行 `python -m chapter6.chunk_feedback` 可离线核对参考输出。程序输出 `maintenance`、`alignment_samples`、`checks` 和 A/B 方案。也可将本练习交给课程运行器，用 `run(ask=...)` 调用 DeepSeek V4 Flash 对照问题、片段和已核验规则，提出二次归因意见。模型意见与原记录冲突，或缺少可核对的原文时，结果进入 `review.pending`，供人复核。在线 A/B 只提供方法，这批回放没有线上实验结果。

从仓库根目录加上 `--live`，即可通过同一个课程运行器调用 DeepSeek Flash。输出用 `--output` 保存。

## 独立运行条件

离线模式执行本课教学数据；使用 `--live` 时，先按[模型配置](../../README-DEEPSEEK.md)配置服务，并安装公共依赖。用 `--output` 指定独立的结果文件。

默认运行计算固定回放的处置与样例。`review.mode` 表示是否追加了模型复核，`online_evaluation.status = design_only` 表示 A/B 部分是一份方案；这两类结果分别验收，不能从离线反馈表推断线上改善。

```bash
python -m pip install -r chapter6/chunk_feedback/requirements.txt
python -m chapter6.chunk_feedback --output chapter6/chunk_feedback/results/offline.json
```

默认终端显示本轮问题、关键证据与结果对照；指定 `--output` 后仍显示课堂摘要，完整轨迹写入文件。需要在终端查看完整结构时加 `--json`；离线回放、模型调用与协议验证的范围会在输出中区分。

## 在自己的项目中使用

选择一个问答失败案例，分别标出原始问题、召回片段、实际使用片段与错误结论，再决定是重切块、补资料还是调整生成。把修改带回[文档问答基线](../vector_qa/README.md)，用原问题和新的独立问题复核，避免只根据好差评维护知识库。
