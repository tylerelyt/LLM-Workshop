# 迭代图检索

## 工程任务

图谱同时保留现行路由、旧版路由和演练记录，必须沿真实访问过的边确认值班团队。

在 [lab.py](lab.py) 中，固定问题、图谱与选边策略，只将 STEP_LIMIT 从 8 改为 3。

解释证据链是否闭合，以及预算减少后哪些结论需要暂缓输出。

## 学员题面

一次模拟支付回调故障进入人工接管。值班平台要知道 **目前由哪个团队负责，以及应该用哪条值班通道通知**。知识图谱里还有迁移前的路由、旧值班策略与演练记录。查错版本会把告警发给已经移交业务的团队。本练习只查询模拟图谱。

你从“人工接管”条目开始。图谱接口每次返回当前节点的正文和可继续探索的边。边的句柄只能在看到它之后使用。每次模型决策都计入预算，总共八步。你需要决定走哪条边、哪些材料仍有效，以及何时已有足够证据。你可以修改检索策略或提示，提交结果时说明为何接受这条证据链。

先运行参考策略，逐项对照 `one_shot`、`trace`、`observations` 和 `evidence`。一次检索虽然看见多个分支，仍未取得完整现行路径；迭代结果应能沿四条实际访问的边连接到责任团队和通知策略。检查最终团队、通道与所引用的原文是否一致。

固定问题、图谱与选边策略，只把 `STEP_LIMIT` 从 8 改为 3。运行前预测会缺少哪段证据，运行后核对轨迹长度、`complete = false` 和 `answer = null`。恢复预算再重跑。继续改进时，仅调整 `_offline_edge` 或 `SYSTEM` 的策略，`GRAPH` 与 `EXPECTED_PATH` 作为独立核验依据。每次运行创建新的遍历状态，旧边句柄不能带到下一轮使用。

- 先跑一轮只展开起点的检索，记下看见了哪些材料、哪些问题仍无法回答。
- 再做迭代式检索，提交每步选择和取得的观察。最终结论须能沿实际走过的边回到起点，并引用当前团队及现行策略的原文。
- 再构造一次无效边或重复请求，证明它不会扩大可见范围。提前耗尽步数时应明确标记证据不足。
- 比较两种方法的图谱展开次数和最终证据。以证据链能否闭合为准，回答措辞可以不同。

## 运行参考实现

用 Python 3.11 或 3.12 执行 `python -m chapter6.graph_search` 即可离线重放。脚本输出一次检索的基线、迭代轨迹、观察、证据链和结论。离线路线只根据已观察到的边名称选择下一步。模型模式复用同一套执行检查。

统一模型适配器约定为 `ask(system: str, user: str) -> str`。将课程提供的 DeepSeek V4 Flash 调用函数传给 `run(ask=ask)`。模型每步只看到问题、已观察材料和可选边，返回形如 `{"edge_id":"E01"}` 的 JSON，或在决定结束时返回 `{"stop":true}`。局部图谱服务根据已发出的边句柄校验并逐步释放下一段材料。证据不足时，`complete` 为 `false`，`answer` 为空。

图谱与证据检查器使用隔离教学数据。`lab.py` 是供教师核对和复现实验的参考实现。独立练习可只发题面和图谱访问接口，保留检索策略和证据检查由学员自行实现。

从仓库根目录加上 `--live`，即可通过同一个课程运行器调用 DeepSeek Flash。输出用 `--output` 保存。

## 独立运行条件

离线模式执行本课教学数据；使用 `--live` 时，先按[模型配置](../../README-DEEPSEEK.md)配置服务，并安装公共依赖。用 `--output` 指定独立的结果文件。

```bash
python -m pip install -r chapter6/graph_search/requirements.txt
python -m chapter6.graph_search --output chapter6/graph_search/results/offline.json
```

默认终端显示本轮问题、关键证据与结果对照；指定 `--output` 后仍显示课堂摘要，完整轨迹写入文件。需要在终端查看完整结构时加 `--json`；离线回放、模型调用与协议验证的范围会在输出中区分。

## 在自己的项目中使用

选择一个确实需要跨关系组合的实际问题，先手工画出能支持答案的最短证据链，再设定搜索预算。比较直接[向量检索](../vector_qa/README.md)和沿图扩展的结果，说明新增结构是否带来可核对的收益。
