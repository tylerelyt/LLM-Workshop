# 语义去重

同一条退款规定被 Wiki 和客服手册各写了一遍。用户问退款期限时，这两条片段反复占用召回名额。更麻烦的是，另一版规定写的是 14 天，字面上也高度相似。删错一条，客服就可能在错误的时点拒绝申请。

你的任务是让在线查询发现候选，交给离线程序判断。确认两段表达的是同一版本、同一规则后，用一条代表原文替换旧索引，并保留每条原文的出处。版本冲突应留下来，供后续判断适用范围。

参考起点在 `lab.py`，已包含 SQLite 索引、任务队列和事务更新。先运行默认数据，核对 `before` 中的 `a-wiki`、`b-manual`、`c-new-rule`，再看 `after` 为什么只剩一个代表和新版规定。沿 `source_ids` 与 `archive` 追溯两份旧原文，检查 `checks` 中的隔离与重放结果。

做一次只改变代表选择的对照：保持规则、版本和权限组不变，将 `KnowledgeIndex._preview` 中等价片段的 `canonical_id` 从 `a-wiki` 改为 `b-manual`。运行前预测代表正文和原文映射会怎样变化，运行后核对旧版仍合并、新版仍保留、两份来源仍能查回。只修改固定判定或接入自己的 `ask`，保留事务和权限检查。程序每次运行创建并关闭本次教学索引，恢复代表选择即可重做。

## 工程任务

两个退款片段意思相同，另一个相似片段却把期限从七天改成十四天。

在 [lab.py](lab.py) 中，固定模型或回放、语料与问题，只改变候选相似度阈值。

决定哪些可合并、哪些应保留为版本冲突，并保留代表原文的来源。

## 动手做

- 在召回结果内发现高相似候选，只比较当前用户有权看到、同属一项规定的片段。在线把无序片段对登记进队列，照常返回结果。
- 写离线处理程序，区分语义等价、规则或版本冲突、暂不确定。让 DeepSeek V4 Flash 审查同义和冲突，用程序约束租户、权限组和版本。缺少确定结论时保留原索引。
- 对确认等价的片段，选一条原文作为代表，建立新索引、保存代表到原文的映射、归档两份原文并移除旧索引。在同一个 SQLite 事务中完成这些动作。
- 对同一个问题重复查询并重放离线任务，再换租户和权限组查询，核对召回和溯源是否仍然正确。

## 怎么验收

- 同一权限内的两条 7 天规定最终只占一个召回位置，14 天的新版仍然可以召回。
- 从代表条目能找到两份已归档的原文、原始版本与条目 ID。读其他租户或权限组的原文时取不到结果。
- 相同查询重复执行不重复入队。离线任务重放不再写入同一代表。
- 离线模型返回无效结果时，旧索引仍可查询，任务可以重试。

## 运行

用 Python 3.11 或 3.12运行 `python -m chapter6.semantic_dedup`，查看 JSON 中的 `checks`、`before`、`after` 和归档记录。课程的 DeepSeek V4 Flash 调用器可以作为 `run(ask)` 的参数注入，签名为 `ask(system: str, user: str) -> str`。直接运行使用固定判定进行离线预演。

练习用 SQLite 和字符二元组模拟索引与距离判断。接到已有 RAG 时，可以复用查询返回的向量距离产生候选，仍在离线判断它们是否可以合并。

从仓库根目录加上 `--live`，即可通过同一个课程运行器调用 DeepSeek Flash。输出用 `--output` 保存。

## 独立运行条件

离线模式执行本课教学数据；使用 `--live` 时，先按[模型配置](../../README-DEEPSEEK.md)配置服务，并安装公共依赖。用 `--output` 指定独立的结果文件。

```bash
python -m pip install -r chapter6/semantic_dedup/requirements.txt
python -m chapter6.semantic_dedup --output chapter6/semantic_dedup/results/offline.json
```

默认终端显示本轮问题、关键证据与结果对照；指定 `--output` 后仍显示课堂摘要，完整轨迹写入文件。需要在终端查看完整结构时加 `--json`；离线回放、模型调用与协议验证的范围会在输出中区分。

## 在自己的项目中使用

从自己的语料中找出表达相似但版本、适用范围不同的条款，先人工标出等价关系再调整去重规则。将更新后的语料带回[向量问答](../vector_qa/README.md)的固定题集，检查来源追溯与答案是否仍成立。
